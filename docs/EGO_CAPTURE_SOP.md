# Ego 采集与处理 SOP

第一次使用先试录一次拿起并放下物体，确认画面和触觉能一起回放。需要安装或练习时，展开下方对应说明。

## 00 设备与标定

接上头戴双目和左手手套。确认左右目对应，活动手指，确认触觉有响应。第一次接入可在设备页保存左右目对应关系。

使用 EXO 时，在「EXO 桌面标定与内参」下载并打印同一张标定板。已有对应镜头的内参 JSON 可在此导入，之后各次录制可选用。

## 01 录制

打开实时录制页，确认两路画面正常、手套有数据，点 **开始录制**。拍完点 **停止并保存**，进入 02。

- **有独立 EXO。** 固定机位，把同一张标定板固定在桌面上。正常录制中拍到桌面板，首尾让各路相机拍到同一个持续更新的二维码。把原始 MP4／MOV 复制到电脑。
- **启用了任务前后视触校准。** 用戴手套的手在镜头前短按一次，松开后点 **开始任务**。做完动作点 **结束任务**，再短按一次后保存。

## 02 导入与复核

- **EXO 录像（可选）。** 点 **导入 EXO 录像**，可以多选。系统立即扫描录像，尝试二维码对时和桌面标定。需要指定镜头内参时，展开「选择已保存的相机内参」。在「对时报告与诊断」点标记可查看识别帧和原片时间。
- **视触复核。** 来到「任务前」和「任务后」，各找出刚接触的画面与触觉开始上升的位置，再点 **确认对帧**。看不清时换视角或点 **跳过本段**。仅在录制时启用视触校准的会话中进行。

确认后点 **去整理**。中途离开时，可以从 01 的会话列表继续。

## 03 整理与验收

点 **开始整理**。这一步把 02 的选择应用到录制，生成供 04 回放和选段的数据。看到整理完成即可进入 04 检查回放。处理有异常时，展开详情查看原因，再按提示回到 02 补资料。

## 04 选段与交接

双目和各路 EXO 在同一个区域回放。已对时的 EXO 跟随顶部时间轴。可在标为「原片预览 · 未对时」的画面内单独播放。

在「自选区间与送入工作流」标记正式动作的起止并命名。点 **应用选区** 检查选段，再点 **加入工作流**。交接时，在「录制文件」中点 **导出完整原始录制 ZIP**。

<details>
<summary>安装与启动</summary>

需要 Windows x64、Python 3.11、匹配的头戴双目和左手手套。EXO 可用固定手机或相机。有多路相机时，准备一块能让各路拍到的二维码屏幕。[Python Windows 下载](https://www.python.org/downloads/windows/)

在 GitHub 点 **Code → Download ZIP**。解压后在 README 所在文件夹打开 PowerShell，运行以下命令。[仓库](https://github.com/foutiam/ego)

```powershell
py -3.11 --version
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r configs\ego-capture-requirements.txt
.\.venv\Scripts\python.exe scripts\serve_ego_capture.py
```

电脑打开终端显示的「采集工作台」，默认地址为 `http://127.0.0.1:8793/ego-capture/`。

若用另一台手机显示二维码，先让它和电脑连同一 Wi‑Fi。在电脑运行 `ipconfig` 找到对应网卡的 IPv4 地址，再用以下命令启动，将示例地址换成自己的。手机打开终端显示的「手机二维码」地址。

```powershell
.\.venv\Scripts\python.exe scripts\serve_ego_capture.py --qr-bind 192.168.1.23
```

</details>

<details>
<summary>保存目录、设备和素材设置</summary>

- **保存位置。** 默认写到解压目录下的 `recordings/`。在 **01 录制 → 设备、路径与会话导入 → 录制保存位置** 可修改录制位置，也能另设导入、导出及 EXO 档案位置。保存后等任务结束，按 Ctrl+C 停止服务，再运行相同的启动命令。旧会话仍可从原目录导入。已有工作站配置可用 `--config` 指定。
- **双目与手套。** 在 00 遮挡一只镜头，核对哪一路变暗。静置基线可在设备页录 3 秒。需要 OpenXR 骨架时，在「设备参数与校验状态 → 设置 EXO 与手套档案」选择配套运行环境的 `python.exe`，重启后按提示标定。历史会话或已有的 Ego `calibration.json` 可以在设备页查看。[QnBot 文档](https://docs.qnbot.com/zh-CN)
- **相机来源。** 电脑直连的 EXO 在实时录制页展开「实时 EXO 相机」，选择对应预览来源。独立 EXO 的电脑槽位保持「不使用」，拍完在 02 添加原片。复制时保留原始帧时间戳。
- **二维码。** 各相机可依次拍同一个持续更新的页面。建议首尾各拍清 5–10 秒，两次有效观察间隔至少 10 秒。用手机拍 EXO 时，可用电脑或另一块屏幕显示码。
- **EXO 桌面坐标。** 在 00 下载 ChArUco 板，按 100% 打印。默认格长 25 mm，实物刻度有差异就在 00 保存实测值。每路相机用同一张固定板，保持镜头、分辨率和裁切一致。固定单视角通常需要匹配内参，只有画面中有足够视角变化时才能从录像估计内参。

</details>

<details>
<summary>检查结果与处理异常</summary>

| 现象 | 检查方法 |
| --- | --- |
| 双目或手套无信号 | 在 01 的设备预览下重选来源。用 Windows 设备管理器查看正确的 COM 号。 |
| 手机二维码打不开 | 检查手机地址、同一 Wi‑Fi 和电脑对应网卡地址。端口冲突可用 `--port 8873 --qr-port 8875`。 |
| 某路对时失败 | 核对原片是否拍清同一屏幕的首尾时间码。二维码残差是拟合误差，可用各路都看得清的一次接触抽查。 |
| 桌面标定待补 | 展开 02 的诊断，核对哪些帧识别到了板。若板清晰且固定，在 00 添加匹配录像镜头和分辨率的内参，再在 02 选用。空间标定留出误差要求 RMS ≤ 3 px。 |
| 视触时间需要核对 | 复核时对比上一帧未接触和当前帧首次接触。任务前后均有效时，整理会在任务区间应用两端估计的延迟，保留原始触觉值与时间。 |

</details>

<details>
<summary>交接、无硬件演练与参考</summary>

接收 ZIP 的同事先解压，把含 `metadata.json` 的整个会话文件夹放到 **01 录制 → 设备、路径与会话导入 → 导入已有 Ego 会话** 显示的目录。送入工作流的片段可在 **物理交互工作流 → 01 片段输入** 并排看双目，点击触觉曲线跳帧，或添加事件标注。

### 无硬件演练

```powershell
.\.venv\Scripts\python.exe scripts\make_ego_capture_demo.py
.\.venv\Scripts\python.exe scripts\serve_ego_capture.py --config demo-station/capture.demo.json --offline --port 8873
```

打开合成会话 `demo-cup-001`。在 02 导入演练目录的 `recordings/exo-inbox/exo1-task.mp4`，查看扫描进度和检测时间轴。可在 02 选择演练预装的 `exo1-lens.json`，观察重新扫描后的桌面标定结果。去 04 把 `5` 至 `13` 秒命名为 `demo-pick-place`，加入工作流并检查回放。
