# Ego 采集与处理 SOP

## 1. 第一次安装

**准备** Windows、64 位 Python 3.11、支持现有串口协议的头戴双目和左手 QnBot 手套、1–3 台固定 EXO、一台与采集电脑同一局域网的手机，以及一块打印后平整固定的标定板。

在解压目录或 Git 克隆目录打开 PowerShell，执行一次：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r configs\ego-capture-requirements.txt
Copy-Item configs\ego-capture.example.json .\capture.local.json
```

打开 capture.local.json：

- output_root 是录制和处理结果目录。可以填绝对地址，例如用正斜杠书写的 F:/Lab/EgoRecordings。相对路径以配置文件所在目录为准。
- import_root 是从另一台工作站导入的会话文件夹入口，exo_video_root 放 EXO 视频，exo_profile_root 放镜头标定 JSON。示例配置这三个目录位于 recordings 下；改变 output_root 时一起调整，或删除这三个可选键以跟随 output_root。
- 对支持的设备默认按 USB VID/PID 识别。只有同类设备不止一台，或电脑的自动选择不正确时，才填写对应的 camera_port_override 或 glove_port_override，例如 COM7。camera_serial 可留空或填实验室实际序列号。
- qnbot_runtime_python 指向同事按厂商说明安装的 QnBot 工具运行环境的 python.exe。原始压感/手套录制走串口。要同时采到经工具生成的 OpenXR 骨架，启动前应配置并核对这个运行环境。

启动采集工作台。把示例 IP 换成采集电脑当前的私有局域网 IPv4 地址：

```powershell
.\.venv\Scripts\python.exe scripts\serve_ego_capture.py --config capture.local.json --qr-bind 192.168.1.23
```

- 电脑打开终端输出的采集工作台地址。手机打开终端输出的二维码地址。手机页面只用于显示二维码。
- 只处理已有录制时可加 --offline；只需要电脑屏幕显示二维码时可省略 --qr-bind。
- 如果手机打不开，先检查两台设备是否在同一局域网、是否用了采集电脑的 IPv4，以及此专用网络是否允许二维码端口。采集网页仍在电脑本机打开。

## 2. 设备与桌面准备

1. 在「标定与同步 → 当前设备标定」确认双目都出画面。遮住物理左镜头，确认并保存实际左右目。检查手套压感随按压变化，按页面完成 OpenXR 标定并采集 3 秒静置基线。
2. 下载「固定 EXO 相机 → 下载标定板」。用 100% 比例打印 ChArUco 8×5 板。默认格长 25 mm，标记边长 18 mm，棋盘外边界 200×125 mm。用尺实测格长，填入页面。固定在不翘曲的平板上。标定时以棋盘平面为桌面参考，板有明显厚度时记录它相对真实桌面的高度。
3. 固定各台 EXO，并固定分辨率、焦距与裁切设置。按机位给文件命名，例如 exo1-task.mp4、exo1-table.mp4。把板固定在桌上的同一位置与朝向，各路单独拍一段清楚的固定板录像，建议约 3–5 秒。正式录制也可包含这段画面，并复用同一个原视频。
4. **有匹配的内参档案**时，将 JSON 放入界面所示的标定档案目录。支持示例格式中的 pinhole 或 fisheye。确认档案属于同一机身、镜头、裁切和分辨率。程序会用这次的固定板录像算或核验当前桌面外参。
5. **没有档案**时，先为该机位另外拍一段内参录像。相机不动，把板在画面中央、边缘和不同距离多角度倾斜。然后把板放回固定桌面位置，拍第 3 步的录像。新估计内参用针孔畸变模型；已知鱼眼设备优先导入对应的鱼眼档案。
6. 头戴相机在需要桌面空间位姿的阶段应尽量保持桌面板可见。板看不见的帧保留原图和时间戳，桌面位姿留空。空间状态和对时状态分别验收。

## 3. 每次正式录制

1. 在电脑开始头戴双目与手套录制，再开始各路 EXO 原始录像。
2. 所有相机在正式动作前拍到手机屏幕上的**同一个持续开启的二维码页面**约 5–10 秒。完成动作后，再让所有相机拍到同一个码约 5–10 秒。两段有效观察间隔至少 10 秒，中间不刷新或关闭手机页面。
3. 停止录制，确认双目和手套会话已保存。保留 EXO 原始 MP4／MOV，不剪辑、不重编码。把每路原视频及标定录像复制到界面显示的 EXO 导入目录。
4. **敲击/按压只用于工作站首次验收、更换设备或采集链路、发现同步异常。** 头、中、尾拍到手套触发和相机中的同一个接触动作，录后点「检查视触延迟」。二维码用来把相机曝光时间轴映射到采集电脑；手套使用电脑接收串口包的时间，延迟报告单独看。

## 4. 录后处理和交接

1. 在「录制目录」选会话，等待自动整理完成，或者手动点「整理录制」。核对两路画面、手套、帧数、接收时间轴和可用的骨架。
2. 打开「标定与同步 → 二维码对时」选同一会话。「固定 EXO 相机」预置两路，可以停用一路或添加第三路。逐路选择原始录像、固定板录像、内参档案或内参录像。输入实测格长，点「计算 EXO 标定与对齐」。
3. 对照结果页逐路检查桌面标定留出误差、QR 偏移/漂移和二维码残差。桌面误差、相机时钟残差、手套物理延迟是三项不同的指标。当前桌面自动验收使用留出画面 RMS ≤3 px。QR 处理要求每路有足够间隔的首尾证据；当前量级受视频帧率和屏幕更新影响。第一次实机验收保存一次独立视触检查。
4. 处理成功后，会话目录中的 derived/exo-session.json 保存相机角色、档案指纹和时间映射。它指向本条会话里保存的原视频、逐帧索引和标定结果。头戴双目与 EXO 索引的 session_s 共享电脑时间原点。手套保留同一原点下的接收时间。标定板坐标以板角为原点、沿棋盘两条边为 X/Y，文件用米并明确保存从板坐标到相机坐标的变换。
5. 在回放中挑选有效拿放区间并登记片段。用「导出」生成该会话 ZIP。给同事时保留顶层目录名为会话编号（解压后放到该工作站的录制导入目录）。处理源代码与实拍录像分开发。
6. 对于异常：内参不匹配时选对应分辨率的档案；桌面误差高时确认板平整、机位固定并补拍；只有一段 QR 时补录正常首尾；头戴桌面位姿覆盖低时把板放到动作区旁边、确保不被手遮住。

## 实机交付验收

在同事的 Windows 电脑，从独立源码包安装一次。分别用 2 台和 3 台 EXO、头戴双目、同款手套，录一段拿放。完成以下检查再将工作站标记为可用：

- 设备自动识别或显式 COM 配置正确；双目、压感和配置的 OpenXR 骨架都能回放。
- 每路能绑定正确的原始视频。固定板留出误差通过，EXO 档案与本机位和视频尺寸一致。
- 所需各路有首尾 QR、偏移及漂移。核对一次可见接触事件与手套触觉记录，保存误差和关键帧。
- 能登记片段并导出，换一个录制目录导入后，原始流、EXO 文件、标定档案、时间索引和独立工作台登记的片段仍可读。
